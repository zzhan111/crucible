# Crucible「专家访谈 → 契约」原型 v0.1：拥挤诊断 + 改版方向（v0.2 设计阶段）

> 范围：只诊断、只出方向，**不做完整改版**。原型目录 `/workspace/elicit-proto/` 只读，没有改动（核对过：11:00 之后该目录内没有任何文件被修改）。
> 本目录：`/workspace/elicit-proto-v0.2-design/`
> 约束：不删任何功能和数据，只改层级、留白、密度和布局。
> 所有截图都由 playwright-core + 本机 Chrome 渲染，`deviceScaleFactor=1`，渲染前先清空 localStorage，用初始示例数据。字体是 Linux 上的 Noto CJK；在 Mac 的 PingFang 下宽度会略有不同。

## 0. 一句话结论

1366×768 下，界面同时有 **3 根常驻栏**：左 220 + 右 340 = 560px，占屏宽 41%。顶部还有 **191px 的粘性头部**（屏高的 25%）和每屏一张 **92–112px 的说明卡**。实际工作内容从 y≈314–373 才开始，已经到屏高的 41–49%。主区只剩 806px，里面的规则卡片**又全部完全展开**（每张 322–366px），右栏还**把同一批规则再列一遍**。所以拥挤的根因不是“东西多”，而是三件事：**同一时刻所有东西都以同等权重摊开**、**同一份信息出现两次**、**没有任何渐进披露**。

## 2. 所有方向共用的“共享层”（`tools/shared.css` + `tools/shared.js`）

这一层针对 P0-2、P1-2、P1-3、P1-4、P2-1、P2-3，三个方向都包含：
1. **头部压成 2 行**（191 → 94px）。场景槽位只显示「被评对象」一项，点开弹出层能看到 被评对象 / 用途 / 代价 全文。示例横幅改成头部的「●含示例 ◇模拟」小标记，点开是原横幅的全文加「清除示例」按钮。
2. **说明卡默认折叠成一行标题**（这一屏的核心问句），点「说明 ▾」展开全文。全文一字未删。
3. 字号收敛为 5 级刻度，间距收敛为 4 的倍数刻度。卡片去边框，改用浅阴影。
4. 「模拟」「示例」从药丸改为纯文字小标记。所有标记位置不变、数量不变。
5. 矩阵格子去掉饱和黄底和虚线框。
6. 规则的“摘要行”部件：`范围 · 条件 → 判定 · 例外 N · 命中 N · 警示（未溯源 / 0 命中）`，供三个方向复用。

实现方式：方向页面 = `baseline/src`（原型源码的只读副本，与原型一字不差）+ 共享层 + 方向层。方向层只**追加** CSS 和 JS 覆盖（同名函数后声明生效），模型、求值、回归、RDR 阻止、导出等逻辑都没动。构建命令：`python3 tools/build_dir.py A|B|C`。

## 3. 三个方向

### 方向 A：聚焦模式（Focus）——契约改为按需抽屉 + 图标导轨 + 规则折叠
- **一句话**：把屏幕还给“当前这一步”，契约平时只显示一个**实时状态胶囊**，需要时再拉出抽屉。
- **改了什么**
  - 左栏改为 64px 图标导轨：logo、＋新场景、场景头像（带分歧数红点和完整悬停提示）、↺重置、ⓘ说明。点 logo 或 ⓘ 会展开为 260px 浮层，内容与原侧栏完全一致；在浮层里执行操作后浮层自动收起。
  - 右侧契约面板改为 400px 抽屉，默认收起。头部右侧常驻**状态胶囊**，显示「一致 4/7 · 常识 4/7 · 待办 4 · 契约 v1 ⟨」，数字实时更新，点击打开抽屉；抽屉内容与原面板一致（指标、5 个分区、导出）。Esc 或抽屉内的 ⟩ 可关闭。
  - ③ 规则卡片默认折叠成 52px 的摘要行；R1 演示为展开态。展开后是完整卡片（字段分组 + 「命中商品 ▴」第二层披露 + 编辑 / 停用 / 删除）。另有「全部展开 / 全部收起」按钮。悬停摘要行会出现「编辑」快捷按钮。
  - ④ 顺序调整为：商品 + 两个判断 → **提问框**（首屏）→ AI 追问 → 「契约的理由 | 区分特征」并排。
- **实测（1366×768）**：主区 806 → **1302**；头部 191 → **94**；工作内容起点 y 373 → **197**；③ 列表 2774 → **792px**；④ 提问框 y 627 → **276**。
- **代价**
  - 契约平时看不到全文，只剩胶囊里的 3 个数字。“边改边看契约”变成要多点一次；抽屉打开时会盖住主区右侧约 400px，没法和主区内容左右对照。
  - 规则折叠后，**来源原话也被折起来了**。溯源是这个产品信任感的核心，这一点要权衡；可以在摘要行加一个「有原话」小图标或原话前 12 个字。
  - 打开的抽屉会盖住头部的状态胶囊，关闭要用抽屉自己的 ⟩ 按钮或 Esc（冒烟测试里发现的）。
- **保留了什么**：原有 55 个交互动作，在冒烟测试中可见可点的有 54 个（见 §4）；`im-reset-cat` 只在手动改过归类后出现，原型基线跑同一流程也没碰到。拖放、RDR 阻止 / 解除、导出 JSON / YAML、会话切换 / 新建 / 重置全部跑通。
- **截图**：`shots/after/A-1366-rules.png`（③ R1 展开，其余折叠）、`A-1366-rules-drawer-open.png`（抽屉打开）、`A-1366-repair.png`、`A-1366-triad.png`、`A-1366-pile.png`、`A-1366-matrix.png`、`A-1366-rail-open.png`（导轨展开）、`A-1440-rules.png`、`A-1100-repair.png`

### 方向 B：步骤向导（Stepper）——一次一屏 + 底部契约条 + 规则主从布局
- **一句话**：把五个屏当成一条有进度的流程来走，主区全宽；契约收成底部的摘要条，点开是带标签页的底部面板。
- **改了什么**
  - 去掉左栏。顶栏放 品牌 + 场景切换下拉，下拉里有 场景列表（含规则 / 标注 / 分歧计数）、＋新场景、↺重置、原型说明。
  - 页签改为**步骤条**：编号圆点、连接线、每步的计数（「分歧 3」标红），已完成 / 当前 / 待办三态。每屏底部有「← 上一步 / 下一步 →」。
  - 契约面板改为 **56px 底部摘要条**：一致 / 常识 / 专家规则三个指标，规则 8 · 维度 1 · 样本 7 · 待办 4 · 记录 N 五个分区按钮，以及导出 JSON / 导出 YAML / 预览。点任一分区按钮，会升起 52vh 的底部面板，**一次只显示一个分区**；规则分区用双列网格。
  - ③ **主从布局**：左边 340px 的紧凑规则列表（每条 69px），右边是选中规则的完整卡片，顶部加一行「系统理解为」大字（回译句）。
  - ④ 队列改为顶部的**横向案例条**：✗ 分歧 / ✓ 已一致 / ≈ 已接受，带「1 / 7 ‹ ›」逐个翻页。原来的完整队列（含「契约→你」判断和「≠常识」标记）收在「展开完整队列」里。
- **实测（1366×768）**：主区 **1366**（满宽，内容最大 1100 居中）；头部 114（不含 52px 顶栏）；③ 列表 8 条合计 **552px**，页面滚动高度 3293 → **983**；④ 提问框 y = **424**。
- **代价**
  - **“向导”暗示线性流程，但真实工作流是回路**：④ → ③ 改规则 → ④，⑤ → ①，冲突链接到处跳转。“下一步”按钮和步骤三态可能误导用户以为必须按顺序走。
  - 底部条在 768 高的屏幕上永久占 56px；面板升起后会盖住主区下半部分。
  - 切换场景从 1 次点击变成 2 次。
  - 改动面最大（顶栏、步骤条、底部条 / 面板、主从布局、案例条），后续实现成本最高。
- **保留了什么**：冒烟测试中 55 个动作有 53 个可见可点。`toggle-right`（开关契约面板）的功能由底部条的分区按钮和「契约预览 ⌃」接管，所以 DOM 里不再出现这个动作名；另一个是 `im-reset-cat`，原因同上。核心流程全部跑通。
- **截图**：`shots/after/B-1366-rules.png`（主从）、`B-1366-rules-sheet-open.png`（底部面板 · 规则标签）、`B-1366-repair.png`（案例条）、`B-1366-triad.png`、`B-1366-pile.png`、`B-1366-matrix.png`、`B-1366-session-menu.png`（场景下拉）、`B-1100-rules.png`

### 方向 C：契约常驻 · 标签化（Docked + Tabs）——贴合设计文档 §6
- **一句话**：保留“边做边看实时契约”这个核心体验，但把右栏从“5 段全部摊开的长卷”改成**一行指标 + 待办摘要 + 标签页**。依据是设计文档 v0.2 §6：“右边只保留 规则｜维度｜样本 三个标签 + 常驻清单”。
- **改了什么**
  - 左栏改为 64px 图标导轨，与 A 相同。
  - 右栏宽 340 → 320。结构从上到下：一行 3 个指标；待办摘要胶囊「分歧 3 · 其他待办 1 · 未聊到 17 格」（都可点击跳转）；标签页「规则 8｜维度 1｜样本 7｜待办 4｜记录 1」，**一次只显示一块**；导出按钮。规则标签里，原话和常识理由默认单行截断，悬停显示全文。右栏可收成 **56px 竖条**，竖条上仍显示 一致 / 常识 / 专家 / 待办 4 个数字。
  - ③ 改为**表格行**（规则 / 适用范围 / 条件 → 判定 / 例外 / 命中），每行 73px；点击行在原位展开完整卡片和操作按钮。
  - ④ 提问框上移到首屏，与 A 相同；队列保留在左侧，宽 232px。
- **实测（1366×768）**：主区 806 → **982**；头部 **94**；工作内容起点 y **197**；③ 列表 **985px**（含 R1 展开）；④ 提问框 y **276**。右栏不再是 1706px 的长卷，一次只看一个标签。
- **代价**
  - 主区只增加了 22%：② 的待分卡片、④ 的详情在 1366 宽下仍偏紧（见 `C-1366-pile-tab-conflicts.png`）。
  - 主区页签和右栏标签页是两套导航，概念上多了一层。
  - 表格行在条件很长时会折行。
  - 规则仍然在 ③ 和右栏同时出现。重复依旧存在，只是右栏的版本变短了。
- **保留了什么**：冒烟测试中 55 个动作有 54 个可见可点（缺的同样只有 `im-reset-cat`），核心流程全部跑通。
- **截图**：`shots/after/C-1366-rules.png`（表格 + R1 展开 + 右栏标签）、`C-1366-rules-panel-mini.png`（右栏收成竖条）、`C-1366-pile-tab-conflicts.png`（待办标签）、`C-1366-repair.png`、`C-1366-triad.png`、`C-1366-pile.png`、`C-1366-matrix.png`、`C-1440-rules.png`

## 5. 建议

**推荐 A（聚焦模式）为主干，并吸收 C 的“标签化契约”和“折叠竖条”。** 具体组合：
1. 按 A 的外壳做：64px 导轨、头部状态胶囊、③ 折叠卡、④ 提问框上移。它对 P0 三项的收益最大（主区 +62%，③ 长度降到约 1/3.5，提问框回到首屏），而且五个屏的交互和代码结构基本不动，改造风险最低。
2. 抽屉内部用 C 的布局：一行指标、待办摘要、规则 | 维度 | 样本 | 待办 | 记录 标签页，取代 A 抽屉里原样保留的 5 段长卷，同时对齐设计文档 §6。
3. **宽屏（≥1600px）时抽屉可以“钉住”变成常驻**，即退化为 C 的形态。这样可以弥补 A 最大的缺点“看不到实时契约”。
4. ③ 折叠行要露出溯源线索（「有原话」图标或原话前 12 个字），避免“原话被藏起来”。
5. 不建议以 B 为主：五个屏是**回路**（④↔③、⑤→①、冲突到处跳转），不是线性向导，“下一步”和步骤三态的心智模型不对。不过 B 的 ③ **主从布局**在规则超过 15 条以后比折叠列表更适合扫读，可以作为 ③ 的“列表 / 主从”切换视图，等规则多了再引入。

需要 Zink 拍板的点：契约面板默认收起（A）还是常驻（C）？这取决于专家访谈时是否需要**持续看到**契约的变化。
