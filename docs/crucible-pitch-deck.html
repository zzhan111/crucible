CRUCIBLE01 / 13
◆ THE PROBLEM

多智能体系统,协调是个黑箱。

  • 靠聊天消息协调 —— 智能体之间靠聊天消息沟通,出错无法定位谁偏离了标准
  • "好"的标准锁死在代码里 —— 改一条评分规则要改代码、改测试、重新部署
  • 每个团队重造轮子 —— 评分 + 迭代逻辑各自手写,不可复用、不可观测
  • demo 不可信 —— PPT 与 cherry-pick 截图,不是可运行的可执行契约
PAIN · TODAY

"哪个 agent 判断错了?"

在 prompt 黑箱里,没人答得上来。一群智能体只有聊天记录,没有一份谁都能查的对账单。

引擎通用，场景外置
INSIGHT03 / 13
◆ HOW IT WORKS · 一个契约,三件事

契约不是文档,是智能体共享的事实层。

一份契约 ─── 字段 · 硬约束 · 评价维度 · 校准基线
① LOOP · 自动发现缺陷

打分 → 诊断 → 演化

按照硬约束自动检查 → 发现违规不调 LLM 直接修 → Curator 检验新颖度 → 进入下一轮。 3 轮内分数单调上升,提升 < 0.01 即止。

② LIVE ENV · 动态世界

边走边吐事件的模拟器

浏览器可观测环境一路推送 disruption / info_drop / constraint_update。 多智能体从"拿一份死数据打分"升级为"在一个会变的世界里做决策"。 replay 路演 + record 录制双模,L1/L2/L3 安全网兜底。

③ FAST · SLOW · 快慢思考

能算的算,该品的品

硬约束走确定性代码(快 / 零漂移 / 可解释); 评价维度交给大模型(慢 / 有品味 / 肯德尔秩系数校准)。 两层加权出最终分,省一半 LLM 调用。

→ 一份 YAML 同时承载这三件事:智能体不靠聊天,只读这份契约。

HOW IT WORKS04 / 13
◆ LIVE DEMO · 契约即代码

一份 YAML,定义"好计划"。

travel-sequence-v1.yaml
# 好计划的可执行定义
artifact_family: sequence
fields: [time_block, action, cost, source_trust]
hard_constraints:
  - id: time_budget      # ≤ 960 min
  - id: state_mutex      # 互斥态
  - id: continuity       # 相邻 transit
rubric: [cost_fit, source_trust, dining_fit]
calibration: { metric: kendall_tau }
契约发现的 3 个问题
# 同一份契约,3 条硬约束触发 3 处违规
time_budget   — 行程超 960 分钟
state_mutex   — hiking 与 luggage_drop 冲突
continuity    — 相邻节点无 transit

→ 3 轮迭代后分数一直涨 ✓
